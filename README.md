# OCR Сервис

Веб-сервис распознавания документов для локальной сети: изображения и PDF
обрабатываются несколькими взаимозаменяемыми OCR-движками, результат —
аккуратные **DOCX / TXT / ZIP** с реальным форматированием (таблицы, заголовки,
списки). Многопользовательский, с админ-панелью; работает полностью **офлайн** —
все модели крутятся на ваших машинах, ничего не уходит во внешние сервисы.

> Движки — VLM-модели нового поколения: [MinerU](https://github.com/opendatalab/MinerU),
> [Unlimited-OCR](https://github.com/baidu/Unlimited-OCR) (Baidu) и локальная LLM
> через [LM Studio](https://lmstudio.ai/).

## Возможности

- Загрузка одного или нескольких файлов (PDF / изображения) за раз, прогресс по страницам (SSE)
- Выбор движка распознавания на каждую обработку; движки включаются/отключаются в админке
- Вывод: объединённый документ или отдельные файлы; имена результатов с суффиксом движка (`_MinerU`, `_Unlimited-OCR`)
- Настоящее форматирование DOCX: таблицы с границами, заголовки, списки
- Режим без логина: гостевые сессии с автоочисткой файлов и истории (TTL настраивается)
- Приватность очереди: пользователи не видят чужие задачи в SSE-прогрессе
- Закрепление GPU за каждым движком (админка → настройки), применяет `CUDA_VISIBLE_DEVICES`
- Автоочистка хранилища по сроку, лимит объёма, статистика и графики в админке

## Движки

| Движок | Что умеет | Порт | Стек |
|---|---|---|---|
| **MinerU 2.5-Pro-1.2B** | качественный разбор: таблицы, формулы, макеты | 8501 | PyTorch + mineru[pipeline] |
| **Unlimited-OCR (Baidu)** | VLM 3.3B для длинных документов, свежая модель | 8503 | PyTorch + Transformers |
| **LLM (LM Studio)** | понимает картинки, любой мультимодальный чекпоинт | 1235 | OpenAI-совместимый API |

Веб-приложение само растеризует PDF в изображения (PyMuPDF, 200 dpi) и передаёт
движкам только картинки по единому контракту:

```
POST /ocr    multipart: image=<байты>, filename=<имя>
             → 200 {"text": str, "markdown": str|None}
GET  /health → 200 {"status": "ok"} | 503 {"status": "loading"}
```

Каждый движок — отдельный HTTP-сервис со своим виртуальным окружением
(зависимости конфликтуют между собой), поэтому веб-приложение остаётся лёгким
и не тянет ни torch, ни VLM-стеки.

## Архитектура

```
┌──────────────────┐   POST /ocr (PNG)   ┌──────────────────────┐
│  Веб-приложение  │ ──────────────────► │ Сервер MinerU   :8501│
│  FastAPI, CPU    │ ──────────────────► │ Сервер Unlimited:8503│
│ (этот репозиторий)│ ─────────────────► │ LM Studio    :1235/v1│
└──────────────────┘                     └──────────────────────┘
        │  SQLite + файлы (uploads/, results/)
        ▼
   пользователи: загрузка → очередь → прогресс (SSE) → DOCX/TXT/ZIP
```

## Быстрый старт

Требования: Windows, Python 3.10–3.12, NVIDIA GPU.

```bat
git clone https://github.com/<owner>/ocr-webui.git
cd ocr-webui

:: 1. Веб-приложение
install_all.bat

:: 2. OCR-движки (каждый в свой venv)
install_mineru.bat
install_unlimitedocr.bat

:: 3. Запуск всего разом
run_all.bat
```

Движки при первом старте скачивают веса с HuggingFace (MinerU ~2 ГБ,
Unlimited-OCR ~6.7 ГБ). LLM-движок — внешний: установите
[LM Studio](https://lmstudio.ai/), загрузите мультимодальную модель и включите
локальный сервер (по умолчанию `http://localhost:1235/v1`).

Открыть: `http://localhost:2002` · Админ: `http://localhost:2002/admin/login`

### Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `ADMIN_PASSWORD` | `admin` | пароль администратора (смените в продакшене!) |
| `SECRET_KEY` | `CHANGE-ME-in-production` | ключ подписи JWT |
| `AUTH_REQUIRED` | `true` | `false` — открытый режим с гостевыми сессиями |
| `SESSION_HOURS` | `48` | время жизни гостевой сессии |
| `STORAGE_ROOT` | `D:/ocr_storage` | корень хранилища файлов |
| `MINERU_GPU` / `UNLIMITEDOCR_GPU` | `auto` | закрепление GPU движка |

Полный список — в `config.py`.

## Дизайн

Интерфейс следует единой дизайн-системе (нейтральные поверхности, волосяные
линии, один акцент, никаких градиентов). Рабочий прототип техничной палитры
со светлой и тёмной темами — [prototypes/ocr-tech-palette.html](prototypes/ocr-tech-palette.html)
(открывается из файла, переключатель тем сверху).

## Структура проекта

```
main.py            маршруты FastAPI (пользователи, админка, API, SSE)
worker.py          очередь обработки, прогресс по страницам
ocr/               адаптеры движков (единый контракт)
ocr_servers/       HTTP-серверы движков (по одному на venv)
doc_builder.py     markdown → DOCX (таблицы, границы) + TXT
database.py        SQLite (WAL), сиды настроек, идемпотентные миграции
cleanup.py         автоочистка по сроку, гостевые сессии
templates/         Jinja2 + Tailwind CDN
install.py         установщик (меню / CLI: web, mineru, unlimited, all)
run_all.py         запуск/остановка/статус всех сервисов
```

## Отладка

```bat
run_all.bat --status          :: кто жив
run_all.bat --stop            :: остановить всё
curl http://localhost:8501/health
curl -F "image=@page.png" http://localhost:8501/ocr
```

Логи — в `logs/`. База — `ocr_service.db` (SQLite WAL, схема в `models.py`).
